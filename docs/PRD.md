## 1. 背景与定位

### 1.1 现状盘点（v1 已交付能力）

| 模块 | 已有能力 |
| --- | --- |
| 文件管理 | 笔记列表、搜索（标题/摘要）、新建、重命名、删除、导入 .md、按一级标题自动重命名 |
| 编辑器 | CodeMirror 6：行号、当前行高亮、括号匹配、自动闭合、撤销/重做、19 种格式化动作、自动保存（800ms 防抖）、实时统计（行/字/字符）、硬件键盘 Cmd+S/B/I |
| 预览 | marked GFM 渲染、编辑/预览切换、外链系统浏览器打开 |
| 主题 | 浅色/深色/跟随系统 + 持久化，编辑器/预览/界面三处同步 |
| 存储 | 应用沙盒 documents/notes/，已开启 iOS「文件」App 访问（UIFileSharingEnabled） |
| 工程 | Windows 无 Mac 开发链路：Expo Go 真机预览 + EAS Build 云端打包 |

### 1.2 对标分析

| 维度 | Typora | SoloMD | Typora-CN（现状） |

| 平台 | macOS/Win/Linux | 5 平台（含 iOS/Android） | iOS |
| 所见即所得 | ✅（核心卖点） | ✅ Live + 4 视图 | ❌ 编辑/预览切换 |

| AI | ❌ | 14 家 BYOK + Agent 面板 + 本地 RAG + MCP | ❌ |

### 1.3 产品方向

**一期**：补齐 Typora 级别的「感知—编辑—导出」基础体验（数学公式、Mermaid、大纲、图片、HTML/PDF 导出），并支持 **iOS 系统级工作区**（任意指定目录作为工作目录 + 文件增删查改），全部纯本地实现，零外部依赖。
**二期**：演进为 AI-native 笔记本（对标 SoloMD 的差异化竞争点：中文优先 + BYOK Agent + 细粒度行级编辑工具协议），需外部三方服务。

### 3.5 工作区与 iOS 系统文件操作（新增）

> 当前版本笔记固定存放于应用沙盒 `documents/notes/`。本模块引入「工作区」概念：**iOS 上可访问的任意目录均可指定为工作目录**，覆盖「读取指定路径」与「文件增删查改」两大诉求。全部基于系统文件夹选择器与本地文件 API，零外部服务，符合一期判定标准（§2）。

| 编号 | 需求 | 优先级 | 预估 | 描述 | 验收标准 | 技术要点 |
| --- | --- | --- | --- | --- | --- | --- |
| WS-01 | 读取指定路径作为工作目录 | P0 | 2d | 通过 iOS 系统文件夹选择器（「文件」App：iCloud Drive、「我的 iPhone」下任意文件夹）选定目录作为工作区；未选择时维持默认沙盒 notes/ | 选中目标文件夹后，列表页即刻展示其中全部 .md；完全杀掉 App 重启后仍停留在所选工作区 | expo-document-picker 文件夹模式（getDirectoryAsync）返回目录 URI；所选路径持久化 AsyncStorage；启动时探测访问权限 |
| WS-02 | 工作区文件增删查改 | P0 | 3d | 对当前工作区执行完整文件操作：递归列出、新建笔记、新建文件夹、重命名、删除、跨文件夹移动 | 六项操作全部生效；在 iOS「文件」App 中对同一目录增删文件，回到 App 下拉刷新后结果一致（双向验证） | expo-file-system legacy 对所选目录 URI 读写；移动 = copyAsync + deleteAsync；每次操作后刷新列表缓存 |
| WS-03 | 多工作区管理 | P1 | 1.5d | 工作区管理页：添加新工作区、移除、切换；显示每个工作区名称与笔记数 | 添加两个不同文件夹后可来回切换，各工作区独立保持列表状态 | AsyncStorage 结构化存储工作区数组；列表页顶栏工作区切换入口 |
| WS-04 | 从「文件」App 直接打开 .md | P2 | 1d | 在系统「文件」App 中长按 .md → 共享 → 用本 App 打开，直接编辑并保存回原位置 | 外部打开的文件可编辑、可保存，文件路径不变 | app.json infoPlist 声明 CFBundleDocumentTypes（UTType：net.daringfireball.markdown）；**注意：需 EAS Build 独立安装包/dev client 才生效，Expo Go 内无法验证**，与上架（RL-01）联动排期 |

**一期合计约 45 人天。**

## 4. 二期需求（需外部三方 / 数据库 / Agent 接入）

> 二期每项均标注【外部依赖】——这是与一期的本质区别。

### 4.1 智能层（Agent 接入）——核心差异化

| 编号 | 需求 | 优先级 | 预估 | 描述 | 验收标准 | 外部依赖 |
| --- | --- | --- | --- | --- | --- | --- |
| AG-01 | AI 润色/翻译/总结/改写 | P0 | 4d | 选中文本 → 气泡菜单 → AI 动作，结果以 diff 方式可接受/拒绝 | 选段翻译/润色 3 秒内流式返回；可撤销 | **LLM API（BYOK）**：DeepSeek / GLM / Qwen / OpenAI / Claude / 兼容 OpenAI 协议的任意端点；用户自备 Key，Key 存 Keychain |
| AG-02 | AI 续写/大纲/起标题 | P1 | 3d | 光标处续写；根据全文生成大纲；根据内容建议标题 | 续写风格延续上下文；标题建议 3 个可选 | 同 AG-01 |
| AG-03 | Agent 对话面板 | P1 | 8d | 右侧面板与全部笔记对话；Agent 通过**工具调用**读写笔记（对齐参考资料执行层设计：行级插入/替换，而非全文覆盖） | 「把昨天的会议记录整理成表格」→ Agent 读笔记 → 行级替换 → 用户 accept/reject 每一步 | 同 AG-01 + 本地工具协议（下述 §4.1.1） |
| AG-04 | 语义搜索（RAG） | P2 | 5d | 按语义（而非关键词）检索全库段落 | 搜「部署」能命中「上线/发布」相关段落 | **Embedding API**（OpenAI text-embedding 或国内兼容端点）+ **expo-sqlite 本地向量库**（余弦相似度内存计算） |
| AG-05 | AI 痕迹清理 | P2 | 1d | 一键清除 LLM 输出痕迹（智能引号、零宽字符、【†source】等） | 清理后 diff 预览 | 无（纯本地规则）——放二期因与 AI 工作流配套 |
| AG-06 | 定时 Agent 任务 | 远期 | — | cron/on-save 触发 Recipes | — | **iOS 后台执行限制**，需 BGTaskScheduler + dev build，暂缓 |

#### 4.1.1 Agent 工具协议（AG-03 的落地规范，源自参考资料「执行层」设计）

Agent 可调用的本地工具（function calling schema），全部细粒度：

| 工具 | 参数 | 说明 |
| --- | --- | --- |
| list_notes | query? | 列出笔记（标题/路径/摘要） |
| read_note | path, start_line?, end_line? | 读笔记（支持行区间，非全文） |
| search_notes | keyword | 关键词全库搜索 |
| insert_lines | path, after_line, lines[] | 指定行后插入 |
| replace_lines | path, start_line, end_line, lines[] | 行级替换 |
| rename_note | path, new_title | 重命名 |

写入类工具默认只读模式，需用户在面板中显式开启写权限 + 每步 diff 可 accept/reject（参考 SoloMD 的安全护栏设计）。

### 4.3 数据与同步

| 编号 | 需求 | 优先级 | 预估 | 描述 | 验收标准 | 外部依赖 |
| --- | --- | --- | --- | --- | --- | --- |

## 9. 附录：快捷键总表与 Win ↔ iOS 键位映射

### 9.1 物理键位映射（Windows 键盘 ⇄ iOS）

| Windows 键盘按键 | iOS 对应键 | 说明 |
| --- | --- | --- |
| Win 键 | ⌘ Command | **主修饰键**，所有快捷键首选 |
| Alt | ⌥ Option | iOS 等价 Option |
| Ctrl | ⌃ Control | 少量命令使用 |
| 字母 / 数字键 | 一一对应 | 布局差异只影响个别符号键位置，快捷键组合不受影响 |

### 9.3 快捷键默认表与自定义（含冲突检测，对应需求 EX-08）

**默认一套**：App 内置 §9.2 总表作为唯一默认方案，开箱即用、不可删除。

**自定义修改**：设置页展示完整快捷键表，逐条点击进入「按键录制」模式，按下新组合即完成修改。修改时按以下三类规则**实时冲突检测**：

| 冲突类型 | 示例 | 处理策略 |
| --- | --- | --- |
| ① 与其他命令冲突 | 把「加粗」改成 ⌘I（已被「斜体」占用） | 拦截保存，提示「与【斜体】冲突」；两个选项：**取消** / **转移**（清除旧命令的快捷键，让新命令占用，旧命令变为「无快捷键，仅命令面板可达」） |
| ② 系统保留组合 | ⌘Space（聚焦搜索）、⌘⇧3/⌘⇧4（截图）、⌘H、⌘⇧H 等 iOS 系统级组合 | 直接拦截，提示「系统保留组合，请换一组」 |
| ③ 文本编辑惯例键 | ⌘C / ⌘V / ⌘X / ⌘A（系统剪贴板与全选） | 不进入注册表；其他命令改到这些组合时拦截提示「与系统文本编辑冲突」 |

**其他规则：**

- 录制过程中实时高亮：按下组合后 300ms 内显示检测结果（可用 ✓ / 冲突 ✗ + 原因）
- ⌘Z / ⌘F / ⌘/ 等编辑器内置命令在注册表内，属于类型 ①，可被自定义或转移
- 每条命令允许「清除快捷键」（无快捷键状态，仅命令面板可达）
- 「单条恢复默认」与「全部恢复默认」双入口
- 自定义配置持久化 AsyncStorage，与主题设置同级管理

**技术实现**：快捷键注册表维护「命令 ID → 组合」映射 + 反向索引「组合 → 命令 ID」实时查重；修改完成后经 CM6 **Compartment** 动态重建 keymap 即时生效，无需重启；全局命令部分同步重建 WebView 桥接监听表。

### 9.4 实现决策说明

Expo 托管工作流（Expo Go）**没有原生全局热键 API**，因此文件/视图类全局命令的快捷键不放在 RN 层监听，而是在 WebView 层用 CM6 keymap 捕获后经桥接协议调用 RN 功能（新建/保存/搜索等）。收益：一份实现同时覆盖软键盘场景与外接键盘场景，且不依赖 dev build。
